# 集成指南：强绑定功能怎么替、AI 怎么接

> 这份文档解决两件事：
> ① 作者环境里那些**别人没有的东西**（私有 LLM 池、Obsidian、特定 OCR、外部服务通知、所内模板），你用什么替；
> ② 怎么让 **AI 助手**（Claude Code / WorkBuddy / Cursor）安全地在这套工作台上干活。
>
> 原则：**工作台只负责数据与流程，智能能力一律外挂。** 外挂可替换、可关闭、可审计。

---

## 一、五个强绑定功能与替代方案

### 1. AI 助理 / 智能提醒（原：作者的本地 LLM 池 8788）

| 项 | 说明 |
|---|---|
| 它做什么 | 读台账 → 生成「今天该盯哪些事」的提醒；页面内对话问答 |
| 原实现 | 作者自建代理（127.0.0.1:8788，带选号与额度池） |
| **替代** | **任意 OpenAI 兼容端点**：Ollama / vLLM / LM Studio / 自建代理 / 云端 API |
| 配置 | `llm.base_url`、`llm.model`、`llm.api_key_file`（密钥放文件，不写进配置） |
| 不配的后果 | 助理页显示「未配置」，其余页面完全正常 |

本地 Ollama 示例：

```json
"llm": {
  "base_url": "http://127.0.0.1:11434",
  "model": "qwen2.5:14b-instruct",
  "api_key_file": ""
}
```

云端（注意：**只发台账字段与目录名，不发案卷正文**；介意的律师请只用本地模型）：

```json
"llm": {
  "base_url": "https://api.example.com",
  "model": "your-model",
  "api_key_file": "D:/secrets/llm-key.txt"
}
```

验证：`curl http://127.0.0.1:8899/api/assistant/reminders` 返回 `llm.ok = true`。

**边界不变**：助理的上下文永远是「六源白名单」（台账字段 + 任务 + 期限 + 日程 + 案卷目录名 + 客户备注），
不读案卷正文、不读电话微信。换任何模型这条都成立，因为它写在 `assistant_ops.py` 的取数函数里，不是提示词。

### 2. 知识库同步（原：Obsidian vault）

| 项 | 说明 |
|---|---|
| 它做什么 | 把案件要点写成 Markdown 案件页、归档进知识库 |
| 原实现 | 固定 Obsidian vault 路径 + 特定目录结构 |
| **替代 A** | 任意 Markdown 目录：把 `wiki.root` 指到你的笔记库根目录即可 |
| **替代 B** | 不用它：工作台的台账 + 案卷目录已经能独立工作 |
| 配置 | `wiki.root`（当前版本仅用这一个；`wiki.case_dir` 为预留字段，未实现） |

如果你的知识库是 Notion / 语雀 / 飞书文档，**不要硬接**——那需要写适配层（见第四节「扩展点」）。
更好的做法：让 AI 读工作台导出的 Markdown，再自己发到目标平台。

---

### 3. 本地 OCR（原：作者的 PaddleOCR 环境）

| 项 | 说明 |
|---|---|
| 它做什么 | 收件箱 PDF/图片 → 文字，供归位建议与检索 |
| 原实现 | 固定路径的 `paddleocr_ov` 解释器 + `ocr_contract.py` |
| **替代** | 任何命令行 OCR：约定「输入文件 → 输出 .md/.txt」即可 |
| 配置 | `ocr.enabled`、`ocr.python`、`ocr.script` |
| 不配的后果 | 入库页「本地识别」按钮不可用，其余功能正常 |

适配器只需满足两条约定：

```
<python> <script> <输入文件> <输出目录> [--verify]
→ 在输出目录生成与输入同名的 .md（UTF-8）
→ 退出码 0 = 成功
```

推荐：PaddleOCR / RapidOCR / 讯飞离线 SDK / macOS 的 Vision 框架。
**案件材料一律本地识别**；只有明确非案件材料（公开法规、论文）才考虑在线服务。

---

### 4. 期限提醒（原：Windows toast + 外部服务气泡）

| 项 | 说明 |
|---|---|
| 它做什么 | 到期前 60/30/14 天提醒；开庭日提醒 |
| 原实现 | Windows toast（PowerShell WinRT）+ 外部服务气泡端口 |
| **替代 A** | 只用页面内提醒：不配任何东西，打开工作台首页就有红点与清单 |
| **替代 B** | webhook（**需自行扩展**，约 20 行）：在 `deadline_check.py` 推送段加一个 POST；配置项 `notification.webhook_url` 已预留 |
| **替代 C** | 系统计划任务 + `python deadline_check.py --no-toast`（只刷数据，不弹窗） |

提醒内容只含「案件名 + 日期 + 待办」，**不含当事人联系方式**，可以安全推到群里。

---

### 5. 文书模板（原：所内委托材料 / 所函模板）

| 项 | 说明 |
|---|---|
| 它做什么 | 委托六件套、所函，复制模板 + 定点替换 |
| 原实现 | 所内 `.docx` 模板 + 41 处标记化变量 |
| **替代** | 放你自己的模板进 `templates/委托材料/`，变量写成 `{{ 变量名 }}` |
| 必需变量 | 委托人、相对方、案由、法院、承办律师、案号、收费等（见 `commission_ops.DOCS`） |

用 `docxtpl` 语法：`{{ client }}`。生成后程序会扫描残留的 `{{`，有残留即报错——**宁可让文书里留占位符，也不要静默填空白**。

## 二、给 AI 的三套剧本

> 前提：AI 通过**命令行**操作这台机器，不是通过聊天窗口。
> 装一个 `write-guard`（写前 `assert`、写后 `stamp`），防止 AI 覆盖手改过的文书。

### 剧本 A · 让 AI 改代码

```
读 AGENTS.md → 按「常见任务怎么下手」定位文件 → 改 → 跑三件套 → 交改动清单
```

给 AI 的原话可以就这一句：

> 读 AGENTS.md，按里面的红线与任务表改。改完跑 `compileall` 和 `smoke_views.py --demo`，把结果贴给我。

**禁止**：让它直接改 `data/` 或台账原文件；它只能改代码，数据由人点确认。

### 剧本 B · 让 AI 读台账、做分析、写报告（只读）

```
① python ledger_ops.py list                     # 各 sheet 有哪些案、状态分布
② python ledger_ops.py show --sheet 案件        # 取结构化行
③ 把行数据交给 AI → 生成 Markdown 分析
④ 报告写到 docs/ 或案件夹 08-过程文件/（人来决定）
```

**禁止**：让 AI 直接 `openpyxl.save()` 台账。要回写只能走 `ledger_ops.apply_progress_guarded`（五重闸）。

### 剧本 C · 让 AI 整理收件箱（必须人工确认）

```
① python case_ops.py intake --case <案卷夹>            # dry-run，只出计划
② 人看计划 → 认可
③ python case_ops.py intake --case <案卷夹> --apply     # 执行（只移动，不删除）
④ 复查：目标夹有文件、源夹已空、intake-log.md 有留痕
```

这套流程的价值不在「AI 会归类」，而在**每一步都可停下来看**。

## 三、扩展点：想接自己的系统，改哪里

| 想接什么 | 改哪里 | 约定 |
|---|---|---|
| 新的数据源（案件来自别的系统） | 写一个 `xxx_ops.py` 提供 `read_rows(sheet)` 同签名函数 | 返回 `[{'_row': n, '字段': 值}]` |
| 新的文书类型 | `templates/` + 复制 `sohan_ops.py` 的结构（plan / apply 两段） | plan 必须可 dry-run |
| 新的提醒渠道 | 抄 `deadline_check.py` 的推送段 | 推送失败要降级，不能阻断数据刷新 |
| 新的页面 | `static/app.js` 的 `VIEWS` + `app.py` 路由 | 视图函数必须能在 Node 里裸跑 |
| AI 接入层 | `assistant_ops.py` 的 `get_local_cfg()` + 六源取数 | 不许扩大数据源，除非先过「三问」 |

## 四、如果你想要「更像一个产品」

这套代码刻意保持「单机 + 零依赖 + 可读」。要往产品化走，缺的是这三块，可按需补：

1. **多用户与权限**：现在是单人本地；多人共用需要换成真正的服务端（FastAPI + 数据库 + 认证）。
2. **台账之外的数据模型**：现在台账是唯一事实源；接 OA 需要引入同步层与冲突解决。
3. **审计日志**：现在写操作写 `workbench.log`；合规场景需要不可篡改的操作流水。

在这三块补齐之前，**不建议直接给全所多人使用**——单人本地是它能保证「数据不外发」的前提。

## 五、两个需要单独说明的模块

### `court_sms_ops.py`（法院短信 → 文书拉取）

走的是「一张网」送达短信里的**纯 API 路径**：短信里的链接自带签名参数（`qdbh` / `sdbh` / `sdsin`），
POST 即可取文书列表，不需要登录、不需要验证码。代码只做解析与下载，**不上传任何东西**。

⚠️ 使用前请自行确认三件事：

1. **合规**：这是对接法院系统的非公开接口，仅供个人办案使用；不要批量爬取、不要用于其他目的。
2. **稳定性**：接口与参数随时可能变，失败时按报错排查，不要当成 bug 反复重试。
3. **数据**：下载的文书直接落 `00-收件箱`，属于案件材料，**不得外发**。

不想用就留着不用——它不参与启动，也不影响其他页面。

### `export_batch_data.py`（台账 → 批量文书数据）

把台账行转换成「批量出文书」所需的表格，原实现绑定作者自己的批量文书系统目录
（配置项 `paths.batch_dir` / `paths.batch_backup`，默认落在 `demo/批量文书`）。

**替代思路**：如果你用 Word 邮件合并，只需要「台账行 → 一行一案的宽表」；
可以把它当作样例，改成导出 CSV/Excel 给自己的合并模板，不必沿用整个模块。

## 六、一页总结

| 你缺什么 | 怎么办 | 工作量 |
|---|---|---|
| 没有 LLM | 配 `llm.base_url` 指向 Ollama / 云端 | 5 分钟 |
| 没有 OCR | 装 PaddleOCR/RapidOCR，配 `ocr.python` + `ocr.script` | 30 分钟 |
| 没有知识库 | 不配，功能自动关闭 | 0 |
| 没有提醒渠道 | 只用页面内提醒；或扩展 webhook | 0 / 20 行 |
| 没有模板 | 放自己的 docx 进 `templates/`，变量用 `{{ client }}` | 1 小时 |
| 想让 AI 接手改代码 | 读 `AGENTS.md`，装 `write-guard` | 10 分钟 |
| 想接自己的业务系统 | 见第四节「扩展点」 | 按需 |
